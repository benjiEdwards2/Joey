# Joey TV shell (`tv/`)

A thin Kotlin Android TV / Google TV / Fire TV app: a full-screen WebView over the guest Joey Media UI
(`https://media.joeyhome.net`), native Splash / Offline / Settings / Jellyfin-missing / Update screens, and a
hand-off to the official Jellyfin app for playback. Plan: Joey TV `MASTER_PLAN.md` WP-B7 (shell) and WP-B8 (releases).

| | |
|---|---|
| applicationId | `net.joeyhome.media` (Q35, permanent); debug `net.joeyhome.media.debug`, label "Joey Media (dev)" |
| minSdk / target | 28 (Q42) / 37 |
| Flavors | `sideload` (v1: self-updater, `REQUEST_INSTALL_PACKAGES`) and `store` (declared, empty: no updater) |
| Version | `tv/VERSION` (`versionName`, `versionCode` = Australia/Sydney cut date + `nn`, `minVersionCode`); notes in `tv/NOTES.txt` |
| UI | plain Views, single Activity, no Leanback or Compose; layouts `res/layout/screen_*.xml`, tokens `res/values/` |
| Policies | pure Kotlin in `app/src/main/java/net/joeyhome/media/policy/`, JVM-tested in `app/src/test/` |

## Build via Actions

There is no local JDK or Android SDK on the laptop. Every push to a `joeytv-*` branch that touches `tv/**` or
`.github/workflows/tv.yml` runs `.github/workflows/tv.yml`:

```
gradle -p tv lint testSideloadDebugUnitTest assembleSideloadDebug
bash tv/ci/check_apk.sh ...   # aapt2 badging: package, sdkVersion 28, leanback launcher; permissions; 320x180 banner; TV lint ids
```

Watch and fetch from PowerShell:

```
gh run list -R benjiEdwards2/life-dashboard -w tv.yml -L 3
gh run watch -R benjiEdwards2/life-dashboard <run-id>
gh run download -R benjiEdwards2/life-dashboard <run-id> -n app-debug.apk -D $env:TEMP\jm
```

The `tv-reports` artifact holds the lint HTML/XML and the JVM test results. Gradle is pinned in the workflow
(`gradle-version`); the project has no committed wrapper jar yet. Launcher assets are generated by
`python tv/tools/make_tv_assets.py` from `hub/static/icon_source.jpg`.

Debug builds are signed with the committed, public DEBUG key in `app/debug-signing/` (see its README), so every
CI debug APK has the same signature. The release key never enters git (WP-B8/B9).

## Install with adb

adb lives at `%LOCALAPPDATA%\Android\platform-tools` (user PATH, D-P11). On the TV: Developer options →
Wireless debugging → Pair device with pairing code.

```
adb pair <tv-address>:<pair-port>
adb connect <tv-address>:<port>
adb install -r $env:TEMP\jm\app-debug.apk
adb shell am start -n net.joeyhome.media.debug/net.joeyhome.media.MainActivity
```

`-r` keeps the app's cookies (same debug signature). Uninstall with `adb uninstall net.joeyhome.media.debug`.

## Dev loop: laptop UI over adb reverse

Point a debug build at the laptop's dev server without touching the firewall (no admin, the server stays on
localhost):

```
adb reverse tcp:8850 tcp:8850
```

Then on the TV, on the Splash or Offline screen, hold OK for 2 seconds → Settings → "Laptop via adb reverse" fills
`http://127.0.0.1:8850` → Save. Debug builds accept `http://` overrides; release builds accept `https://` only. "Use
defaults" goes back to the baked hosts. The Jellyfin address field accepts a port (default
`https://jellyfin.joeyhome.net:8443`).

Inspect the WebView from the laptop: Chrome or Edge → `chrome://inspect` (debug builds enable WebView debugging).

## Contracts with the server

### User agent (D-P8)

The WebView user agent is the device default plus ` JoeyTV/<versionName> (<versionCode>)`, e.g.
`... JoeyTV/0.1.0 (2026102101)`. The server switches TV mode on when it sees `JoeyTV/` (the `?tv=1` cookie does the
same for desktop testing).

### Back and the `/healthz` `home` field

The Splash calls `GET <ui>/healthz` (5 s timeouts). HTTP 200 = reachable. The guest front's JSON carries
`"home": "/a/<shelves id>"` (WP-B1); if it is missing or null, the shell reads the `Location` of `GET <ui>/` (303),
and failing that it learns the path of the first UI page loaded. The value is cached for the session and never
hard-coded.

Back, in order:

1. a native screen is open → that screen handles it (Settings / Jellyfin-missing / optional update close;
   Splash, Offline and a forced update exit);
2. the page is asked: `window.joeyTV && joeyTV.back && joeyTV.back()`; `true` = handled (closed a dialog);
3. the current path is the home path → exit (Back on Overview exits, DECISIONS D, even with history);
4. WebView history → back;
5. otherwise → load the home path and clear history, so the next Back exits.

### `window.joeyTV` (provided by the server's `tv.js`, WP-B3)

The shell adds no JavaScript interface. It only calls `window.joeyTV.back()` if the page defines it; the function
returns `true` when it handled Back. D-pad focus inside pages is the page's job (`tv.js`).

### Links (Q41)

| Link | Shell does |
|---|---|
| Same origin as the UI host | loads in the WebView |
| Jellyfin origin, exactly `https://jellyfin.joeyhome.net:8443` | hand-off; item id from `id=` in the fragment (`/web/#/details?id=<id>`), none → Jellyfin home |
| `https://jellyfin.joeyhome.net/...` (no port) | blocked: not the Jellyfin origin (the router only forwards 8443) |
| youtube.com / youtu.be | the YouTube app (toast if missing) |
| anything else | blocked, toast "Not available on TV" |

Only main-frame navigations are checked; sub-frames are the page's business. A main-frame network error or HTTP
5xx shows the Offline screen.

### Hand-off

`JellyfinLauncher.open(itemId)`: Jellyfin missing → the "Jellyfin isn't on this TV yet" card (Google Play, or the
Amazon Appstore when the `amazon.hardware.fire_tv` feature is present); an item id with a route intent → start it;
no route, `ActivityNotFoundException` or `SecurityException` → route 3 (the Jellyfin app home via its leanback launch
intent). Each successful start marks "returning from playback", and the next `onResume` reloads the last UI URL.
Settings → "Test hand-off" uses the same call.

**Step 7 seam:** the item route is `PlaybackRoute` in `policy/HandOff.kt`. `PendingPlaybackRoute` (TODO WP-B7
step 7) returns no intent, so every hand-off opens the Jellyfin app home until the WP-B6 decision line is recorded.
Step 7 replaces it with the recorded component, extras and flags, plus a JVM test on the `IntentSpec`.

### Keys

D-pad goes to the focused view. Back is handled by the shell (`dispatchKeyEvent`, and `OnBackInvokedCallback` on
API 33+). Every `KEYCODE_MEDIA_*` key is returned unconsumed, so it belongs to the Jellyfin app. Home never reaches
apps. Holding OK for 2 s on Splash or Offline opens the hidden Settings screen.
